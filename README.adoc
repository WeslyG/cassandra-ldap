= LDAP Authenticator for Apache Cassandra
:toc:
:toclevels: 2

This plugin authenticates Cassandra clients against LDAP and synchronizes access
from direct LDAP group membership. Mappings grant Cassandra role memberships and
direct keyspace permissions. An ownership journal supports revocation without
adopting unrelated manual assignments.

== Build and test

Docker with Compose v2, Bash, Make and network access to image/Maven registries
are required for the container-based commands:

[source,shell]
----
make build-all
make test-unit
make check-docs
make integration-all
----

* `build-all` packages all six plugins using Maven 3.9.9 and Java 17.
* `test-unit` runs 18 focused policy, LDAP-security, secret-source and CQL-escaping tests.
* `test-release` runs 12 isolated tests of artifact packaging and evidence guards.
* `check-docs` checks configuration examples/defaults, module versions, local links and test counts without live services.
* `integration-all` (also `integration-systemd`) builds, runs unit/packaging/documentation checks, then tests all adapters in real clusters under systemd with encrypted credentials. It uses disposable privileged test containers; run only on a trusted Docker host.

The build uses the public Maven Central Google mirror configured in
link:.mvn/matrix-settings.xml[the Maven settings]. It contains no credentials.
Each deployable jar is
`cassandra-<module>/target/cassandra-ldap-<cassandra-version>-<plugin-version>.jar`.
Use that shaded jar, not an `original-*.jar`, and do not install a separate base jar.

For a local 4.1 build, install a compatible JDK and configure `JAVA_HOME` or put
`java` on `PATH`, then use `make build-4.1`. `make clean-4.1` removes the base
and 4.1 build directories. Container builds do not require a host JDK.
Runtime Java comes from the Cassandra installation, not the Java 17 build image.

== Installation

. Keep a working native Cassandra superuser available for administration and recovery.
. Configure suitable `NetworkTopologyStrategy` replication for `system_auth` and
  a dedicated `ldap_auth` keyspace in every DC. Repair after replication changes.
. Apply link:conf/access-sync-schema.cql[the journal schema] as a database administrator.
  Ordinary LDAP users must not be able to modify `ldap_auth`.
. Create all referenced Cassandra roles and keyspaces. A missing mapped role or
  keyspace rejects synchronization; the plugin does not create mapped roles.
. Install the matching shaded plugin jar in Cassandra's `lib` directory on every
  node. Remove other versions of the same plugin from the classpath.
. Install identical LDAP YAML policies and configure authentication on every node.
. Restart nodes in rolling order, checking role operations as well as CQL connectivity.

For 3.11, 4.0, 4.1 and 5.0, `cassandra.yaml` contains:

[source,yaml]
----
authenticator: LDAPAuthenticator
authorizer: CassandraAuthorizer
role_manager: LDAPCassandraRoleManager
----

For 2.2 use `Cassandra22LDAPAuthenticator`; for 3.0 use
`Cassandra30LDAPAuthenticator`. The authorizer and role manager are the same.

On 4.1 and 5.0 also configure:

[source,yaml]
----
auth_write_consistency_level: QUORUM
auth_read_consistency_level: QUORUM
----

Do not add unsupported settings to older Cassandra releases. Their adapters
repeat validated native auth mutations at QUORUM. The journal always uses QUORUM.
See link:ACCESS_SYNC.md[Access synchronization] for consistency and recovery rules.

Configure client-to-Cassandra TLS and LDAPS with a trusted directory certificate.
The SASL mechanism transports a username and password; it does not supply transport
encryption itself. The example domain and credentials are not deployment settings.

== LDAP configuration

Pass an absolute path to the YAML file in the node's JVM options:

[source,shell]
----
JVM_OPTS="$JVM_OPTS -Dcassandra.ldap.config.file=/etc/cassandra/ldap.yaml"
----

The loader first tries the property path, or `./ldap.yaml` if the property is
unset. If that file is unreadable, it tries `$CASSANDRA_CONF/ldap.yaml`.
An unreadable explicit path can therefore fall back to the environment location;
verify the chosen path in the startup log. A missing, empty or invalid file
prevents startup. YAML is read with SnakeYAML SafeConstructor from Cassandra's
classpath; the plugin does not bundle another SnakeYAML jar.

link:conf/ldap.yaml[Example configuration]:

[source,yaml]
----
ldap_uri: ldaps://ldap.example.org:636/dc=example,dc=org
ldap_service_dn: cn=ldap-service,dc=example,dc=org
ldap_service_password: REPLACE_WITH_SECRET
ldap_filter_template: "(uid=%s)"

auth_cache_enabled: true
allow_empty_password: false

cassandra_ldap_admin_user: cassandra
consistency_for_role: LOCAL_ONE

group_role_mappings:
  - ldap_group_dn: cn=cassandra-users,dc=example,dc=org
    cassandra_roles:
      - analyst_role
      - grant: SELECT
        keyspace: app
      - grant: ALL
        keyspace: app_archive
  - ldap_group_dn: cn=cassandra-readonly-users,dc=example,dc=org
    cassandra_roles:
      - readonly_role
      - grant: SELECT
        keyspace: app
----

LDAP connection fields are flat top-level keys. Secret deployment can therefore
select a password source without inserting an indented block. Configure exactly
one of the four password keys below, removing the others entirely (including
null/empty keys). There is no fallback between secret sources. The loader does
not expand `${VARIABLE}` expressions or decrypt Ansible Vault values.
link:SECRET_HANDLING.md[Secret deployment] describes systemd encrypted credentials
(recommended), EnvironmentFile, secret files, rotation and Ansible operation.

[cols="2,1,4",options="header"]
|===
|Key |Default |Meaning
|ldap_uri |Required |LDAP/LDAPS URI, including the search base DN.
|ldap_service_dn |Required |Directory bind identity used for user/group lookup.
|ldap_service_password |Exclusive source |Literal nonempty directory bind password; spaces are significant.
|ldap_service_password_env |Exclusive source |Name of an environment variable containing the password, not its value.
|ldap_service_password_file |Exclusive source |Absolute path to a UTF-8 secret file.
|ldap_service_password_credential |Exclusive source |Credential name within systemd's CREDENTIALS_DIRECTORY.
|ldap_filter_template |(cn=%s) |Search filter; login values are escaped before substitution.
|group_role_mappings |Required |Nonempty list of group DNs and Cassandra targets.
|ldap_context_factory |com.sun.jndi.ldap.LdapCtxFactory |JNDI context factory.
|auth_cache_enabled |true |Credential-cache setting on 3.11 through 5.0; never bypasses a fresh LDAP credential check.
|allow_empty_password |true |Accepted configuration field; empty client passwords are always rejected regardless of its value.
|auth_bcrypt_gensalt_log2_rounds |10 |Local bcrypt cost for retrieved credentials; choose an integer from 4 through 31.
|consistency_for_role |LOCAL_ONE |Role-manager lookup consistency, not the journal/write consistency.
|cassandra_ldap_admin_user |cassandra |Existing native administrator used for internal role operations.
|load_ldap_service |false |Use a classpath ServiceLoader implementation of LDAPUserRetriever for credential retrieval.
|===

`-Dcassandra.ldap.admin.user=<role>` overrides `cassandra_ldap_admin_user`.
The administrator must exist, be able to log in and have adequate privileges.
Choosing a name here does not promote an ordinary role to superuser.

WARNING: The role manager creates a Cassandra SUPERUSER role named after
`ldap_service_dn` if that role does not exist. Protect the bind credentials and
review whether that identity belongs to any login-eligible LDAP group. This is
separate from ordinary LDAP user roles, which are created with LOGIN=true,
SUPERUSER=false and no stored native password.

== Authentication and authorization

A native role with a stored password is checked against Cassandra. An incorrect
native password is rejected; it is not accepted as an LDAP fallback. When native
credentials are unavailable, the plugin searches LDAP, requires one matching
entry and verifies its password with an LDAP bind. A login is never interpreted
as a raw LDAP filter.

LDAP users log in with a username, but their Cassandra identity is the resolved
full LDAP DN. That DN appears in role/user listings and is used for grants.
A Cassandra role is both a possible login identity and a permission container:
a LOGIN=false role can hold privileges and be granted to a LOGIN=true user role.

Direct groups are resolved from user `memberOf` and group `member`/`uniqueMember`
attributes. A nonexistent configured group DN is skipped; other directory errors
fail the login. Nested groups and AD primary-group expansion are not supported.
A user must match at least one configured group.

The desired access is the union of all matching mappings. Duplicate memberships
and permissions collapse into sets. A string target names an existing Cassandra
role; an object target grants a permission on a named keyspace. `ALL` expands to
the permissions applicable to keyspaces in that Cassandra version; it is not
passed to the Permission enum. It includes powerful permissions such as AUTHORIZE,
so prefer explicit least-privilege targets.

After credential verification the plugin re-reads groups under a cluster-wide
lock, journals assignments it owns, revokes stale owned access and grants missing
desired access. An operational error rejects the login. Native manual grants
are preserved unless the journal already identifies the assignment as LDAP-owned.
Do not manage the same assignment manually and through LDAP.

A background worker also reconciles journaled users, allowing revocation after
group removal or LDAP user deletion without another login. Revocation is bounded
by reconciliation and Cassandra cache delays, not instantaneous. LDAP outages
preserve recorded rights and reject new LDAP logins; native administrators remain
available. See link:ACCESS_SYNC.md[the operational guide] for policy transitions,
lock recovery, AD limitations and ownership migration.

== Extension points

The `base` module contains configuration, directory lookup and synchronization.
Version modules supply service-provider adapters for Cassandra's execution API.
Do not ship more than one version adapter on a node.

A custom credential retriever extends
`com.instaclustr.cassandra.ldap.auth.LDAPUserRetriever` and is registered in
`META-INF/services/com.instaclustr.cassandra.ldap.auth.LDAPUserRetriever`.
Enable `load_ldap_service` to use it. Group reconciliation still uses the built-in
DefaultLDAPServer lookup; a custom retriever alone does not replace that path.

== Repository hygiene

The credentials in `molecule/integration` and Java test resources are disposable
fixtures for `example.org` or loopback services. They are not production secrets.
Build outputs, local Maven caches and raw integration reports are ignored by Git.
Reports may contain local paths, node addresses and synthetic DNs; review and
redact them before sharing outside the test environment.
